# Sprite 与 Texture 尺寸规范

适用：PSD2UI 正式资源命名链路（Schema 1.5），2026-09-09 起的自动图片识别。这里的 512 × 512 是本工具的默认取舍，不是 Unity 强制规范。

## 美术操作与判断顺序

打开 PSD 后，未手动保存类型的普通图片自动按当前图层边界的宽、高判断。已有的默认 Image 也会重新判断，不需要清空配置或重新建立文档。面板显示当前尺寸和类型；完整预检、导出结果分别显示 Sprite / Texture 数量。

| 优先顺序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | 已手动保存 Image、Raw Image、按钮等组件 | 保留已保存用途 |
| 2 | 已设置九宫、其他 Image 专用参数，或角色必须使用 Image（如 Toggle 选中图形） | 保留 Sprite |
| 3 | 未手动设置，宽 × 高 ≥ 262144 像素（512 × 512） | 独立贴图 Raw Image，导出 `texture/模块名/` |
| 4 | 面积虽小，但宽或高 > 2040 px | 独立贴图 Raw Image，导出 `texture/模块名/` |
| 5 | 其余未配置图片 | Image，导出 `sprite/模块名/` |

2040 是按 2048 图集、两侧各预留 4 px 的保守默认边长，不代表 Unity 对所有图集的硬限制，也不保证小于它的所有图片都能装入同一张图集。图集最终尺寸、Padding 和平台设置仍由 Unity 项目决定；本次不修改这些设置。手动固定 Sprite 的图片不受自动阈值覆盖，过大时应由程序核对实际图集打包结果。

| 图层尺寸 | 面积 | 未手动设置时 |
| --- | ---: | --- |
| 128 × 128 | 16384 | Sprite |
| 256 × 256 | 65536 | Sprite |
| 511 × 512 | 261632 | Sprite |
| 512 × 512 | 262144 | Texture |
| 667 × 128 | 85376 | Sprite |
| 1024 × 256 | 262144 | Texture |
| 720 × 1560 | 1123200 | Texture |
| 2041 × 32 | 65312 | Texture（边长保护） |

这是面积判断，不是“有一条边达到 512 就当大图”，也不是“宽高都必须达到 512”。没有九宫信息时，完整图片作为成本估计；工具不会猜测拉伸区域或自动切九宫。已配置九宫的图片继续按现有方式压缩可拉伸区域并保存边框参数。

尺寸取 Photoshop 快照中的图层像素边界，不取 PSD 整张画布，也不取 Unity 显示时的 RectTransform 尺寸；这不是透明像素占比分析，实际 PNG 还可能受现有导出裁切规则影响。规则只选择资源类型，不缩小 PNG，不强制补齐到 2 的幂。不要为了通过分界而缩小美术原图。

需要覆盖结果时，在组件类型中选择“图片 / Image”或“独立贴图 / Raw Image”，再点击“保存组件配置”。已手动保存的类型会固定，切换图层、重开面板或改变尺寸不会被自动规则覆盖。带有自定义 UV 的既有 Raw Image 同样保留。

资源名保持美术原名。`comm` 表示公共资源归属，但只有导出到 `sprite/` 的资源参与本工具的 Sprite Atlas 路由；公共大图可以保留 `comm_...` 名称并进入 `texture/`。`sp`、`bg`、`bt` 和旧 `@` 后缀不决定类型。同名资源仍须通过实际像素比较；同一文档中同名资源的手动类型也应一致。

重新导出时生成新的 `sprite/`、`texture/` 引用和 `json/` 交付；旧目录中此前生成的 PNG 不自动删除。Unity 导入器以新 JSON 的 `kind` 为准。已经导入项目图集的旧 Sprite 是否仍被图集目录收集，需要在项目中按引用清理后核对，不能仅凭新分类断言旧图集已减小。

## Unity 官方建议与本工具的取舍

Unity 官方建议按照共同使用情况拆分图集：某个 Sprite 被使用时，它所在图集的其他纹理也会加载。同屏、经常共用的小图适合一起打包；少量大背景单独加载可以避免公共图集携带整页背景的成本。[Unity 2022.3：优化 Sprite Atlas 使用与尺寸](https://docs.unity3d.com/2022.3/Documentation/Manual/SpriteAtlasWorkflow.html#Optimized)

独立贴图也有代价：Raw Image 使用独立纹理，可能增加 UI 批次。大图全部独立或小图全部独立都不能保证更快，最终应结合同时显示的界面、纹理切换、加载周期和实际性能验证。因此默认保留小图为 Sprite，允许美术明确覆盖。[Unity uGUI 官方 RawImage 源码说明](https://github.com/Unity-Technologies/uGUI/blob/main/com.unity.ugui/Runtime/UGUI/UI/Core/RawImage.cs)

以 2048 图集作为本工具默认策略的参考。512 × 512 面积约占一张 2048 × 2048 图集的 1/16，作为自动分界能排除整页背景，同时保留较长但面积小的按钮底条。这个比例是选择默认值的依据，不是 Unity 提供的“最佳阈值”；项目有实测数据后可调整 Core 的 `AutomaticImagePolicy`，面板提示与本文应同步更新。

Unity 对 Canvas UI 图集建议关闭旋转，Padding 用于避免相邻图片采样串色，官方默认值为 4 px；Read/Write 会保留额外 CPU 副本。本规则不改变现有图集、压缩、Mip Map 或纹理导入设置。[Unity 2022.3：Sprite Atlas 属性](https://docs.unity3d.com/2022.3/Documentation/Manual/class-SpriteAtlas.html)
