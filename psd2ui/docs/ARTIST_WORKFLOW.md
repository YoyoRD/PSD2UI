# PSD2UI 美术操作

Windows Photoshop 2019（20.0.4）安装 CEP 版：解压交付的 ZIP，双击 `Install.cmd`，重启 Photoshop，在「窗口 → 扩展功能 → PSD2UI」打开面板。无需安装 Creative Cloud 客户端、开发工具或 Node.js。更新也运行同一安装入口，旧插件会备份；具体见 [安装说明](../Plus-ins/PSD2UI-CEP/README.md)。以下操作在 CEP 和 UXP 面板共用。

## 第一步：准备 PSD

打开 PSD，并先保存为本地文件。在插件「01 准备 PSD」中填写「界面所属模块」（例如堡垒争夺使用程序约定的 `baoleizhengduo`），点击「保存所属模块」或「初始化并保存配置」。保存模块也能为新文档完成初始化；看到「已准备」后进入组件配置。首次直接保存组件仍可自动初始化。

`document` 是尚未指定业务模块时的占位值，面板会提示导出前填写。所属模块用于 Unity 的界面 / Prefab 路由，不决定全部图片的归属：图片仍进入各自的 `sprite/comm/`、`sprite/baoleizhengduo/`、`texture/comm/` 等目录。填写模块后要保存，再重新导出 JSON；修改输入框本身不会更改 PSD 或既有交付。模块输入在切换图层时保留，切换到另一 PSD 会显示该文档自己的配置。

「待保存配置」表示尚未写入 PSD；「已保存：按钮」表示已读回保存的组件类型。点击下拉框选择类型只是编辑，最后还要点击保存。底部始终显示操作结果，失败时展开原因，不能把失败当作已保存。

想把所有图层放进一个文件夹：填写「根组名称」，点击「将全部图层放入根组」。工具保留原图层名、层级顺序、位置和显示状态，保存 PSD；已有一个完整根组时不会重复套组。根组是整理文件夹，并不会自动把整个页面设置成按钮或列表。

再次准备文档会同步图层变化并保留已有组件配置，不会重置它们。旧文档若明确配置了某个组作为导出根，只能在该组内配置组件；根组外的保存会给出错误，不会悄悄丢弃。

## 第二步：配置组件

普通图片和文字自动读取；只给需要交互或重复生成的部分配置组件。图片资源名使用小写分组开头、下划线分隔的字母数字段，例如 `comm_bt_0032`、`i_diamond_small`。组名、文字内容自由填写。旧名字的 `@...` 后文会被忽略，不代表任何功能。

单张按钮图片：选图层 → 类型选「按钮 / Button」→「保存当前图层」。切到其他层再切回来，当前类型应显示「按钮」，状态显示「已保存」。未初始化也可以这样操作。

组合按钮：选包含底图、文字和装饰的完整组 → 类型选按钮 → 背景指定底图，标题指定文字 →「保存组件配置」。角色下方会显示「背景 → 实际图层名」等映射。定位角色图层后，可点击「返回正在配置的组件」恢复刚才的角色选择，再保存。

未配置组件的普通组，组件下拉框显示“未设置”，不会沿用上一个图层的图片或按钮类型。空组显示“空组 · 未设置组件”，预检和导出自动跳过；只包含空组的目录也跳过。无需保存“忽略”配置，之后添加内容就会恢复正常导出。已设置组件或已用作角色、模板、状态的组保留用途，继续检查所需内容。

### 复杂组件：从里面向外面配置

「结构化」就是给图层分配用途。按钮需要背景与可选文字，列表需要一整项内容作为模板。工具不会要求你把每个装饰图层都设成组件。

例如，一个含购买按钮的商品列表：

```text
商品列表                 ← 最后选择这里，配置为列表
├─ 商品条目               ← 选择这个完整组作为条目模板
│  ├─ 图标、名称、价格
│  └─ 购买按钮            ← 先选择这里，配置为按钮
│     ├─ 按钮底图         → 背景
│     └─ 购买文字         → 标题
├─ 商品样例二             → 勾选为仅预览样例
└─ 商品样例三             → 勾选为仅预览样例
```

1. 先配里面的购买按钮，保存背景和标题角色。
2. 回到外层商品列表，类型选「列表」。条目模板指定「商品条目」整个组；条目本身可以是普通组。
3. 勾选其余重复条目为「仅预览样例」。它们留在 PSD，不生成为额外正式条目。
4. 设置纵向/横向、条目宽高和间距；滚动窗口的可视宽高与条目大小分开设置。点击「保存组件配置」。

网格同理，以一整格作为单元格模板，另外设置列数和横纵间距。固定页签先配每个内部开关，再配外层页签页面组。列表页签先完成内部列表，再配外层列表页面组。

插件中的「复杂组件怎么整理？」提供按钮、输入框、开关、复杂列表、网格、两种页签和视觉状态的图层树及逐步操作，可边看边配。

### 分组和状态

已有完整组：选组，选择组件类型，查看候选并指定不明确的角色后应用。背景、图标、标题、装饰可共同保留，不要求固定图片数量。普通子组可以嵌套；内层独立组件的图层不能被外层抢用。

尚未分组：多选同级图层，选择组件类型，填写新组名称、角色及所需布局，再使用“组合为组件”。工具按这些配置保持原顺序成组。跨父级或中间夹着未选层时提示原因，避免改变画面；可通过 Photoshop 撤销恢复。

列表/网格：选外组，指定条目模板，明确哪些组仅作为排版样例。样例留在 PSD，但不生成为正式条目。新配置选定模板后，会从同级同尺寸组自动计算方向、格子尺寸、间距和行列数；已勾选预览样例时，以模板和这些样例为计算依据。单模板时读取尺寸，间距与行列数可手动调整。可见范围宽高与条目尺寸分别设置。

自动计算发现间距不一致时，会显示实际范围和平均值，以平均间距生成规则排列；不会移动 PSD 图层。尺寸不一致、重叠或网格缺口不能自动推断时，会显示具体原因。手动修改布局后保留手动值，已保存的布局也不会因选回图层而重新计算；需要更新时点击“根据图层重新计算布局”。计算本身不保存 PSD，点击“保存组件配置”后才写入，成功反馈会列出目标组、图层 ID 和组件类型。模板下拉项也显示图层 ID，以区分重名组。

状态：指定普通状态组和默认状态，预览后恢复原可见性。导出保留全部状态资源，默认状态决定初始显示；业务切换由程序接入。

## 第三步：检查导出

在「03 检查导出」中选择任意可写输出目录，无须命名为 res/UIRes。

新交付统一使用以下三个子目录。Sprite 来自 Image，Texture 来自 Raw Image；`comm` 等图片首段保留资源归属，其中 Sprite 按项目路由进入图集，Texture 作为独立贴图。

未手动设置的普通图片按尺寸自动识别：面积达到 512 × 512 px（262144 像素），或任一边超过 2040 px，使用 Texture；其余使用 Sprite。已保存组件、九宫与必要 Image 角色优先保留。已有默认 Image 会重新判断；手动选定类型并保存可以覆盖自动结果。预检和导出会分别显示两种资源数量。示例与取舍依据见 [图片尺寸规范](IMAGE_SIZE_STANDARD.md)。

```text
输出目录/
  sprite/
    comm/comm_bt_1007.png
    baoleizhengduo/baoleizhengduo_sp_0005.png
    item/item_007.png
  texture/
    comm/comm_bg_0002.png
  json/
    界面名.psd2ui.json
```

Sprite 与 Texture 都按资源自身模块建立子目录，模块不是 PSD 组名或当前界面名。公共 `comm` 资源会进入同一个 `comm` 目录，文件名与 JSON 里的 `module` 不变。

Unity 导入时选择 `json` 中的文件，工具优先读取 `../类型/模块名/图片.png`，缺失时兼容旧 `../类型/图片.png`。旧根目录 JSON 优先读取相邻 PNG。重新导出自己的旧交付时，图片写入模块目录、JSON 迁入 `json`；旧 PNG 保留，避免影响仍使用旧目录的其他界面，因此已有导出目录里可能暂时同时存在旧平铺文件和新模块目录。

“检查”列出图片命名、资源与组件问题，点击问题定位图层。图片名不合法、必要角色缺失或引用失效时先修复。

预检失败时，页面顶部显示问题图层的名称、完整层级路径、原因和定位按钮。点击“定位”会在 Photoshop 中选中该图层；同名图层通过路径和图层 ID 区分。资源冲突会列出涉及的多个图层，输出目录等文档级问题则显示为“文档 / 导出设置”。修改后点击“修改后重新预检”，检查通过后问题列表自动收起。普通空组不阻止导出；已配置的组件变空、缺失角色等问题仍需要处理。

“导出”自动检查并生成 JSON 与图片。同名图片比较实际内容，相同才复用，冲突则阻断并报告来源。失败时恢复本次覆盖的交付文件；若恢复也失败，工具保留备份并撤下 JSON 入口，不能把失败输出当成新版本。

不同 PSD 可以共用 `comm` 等公共图片。选好输出目录后的完整预检与导出会比较 PNG 尺寸、颜色与透明度；像素一致自动复用已有文件，不因压缩或元数据差异弹出冲突。内容不同时显示资源名、已有 JSON、图片路径和当前图层定位。自己的独占图片可以正常更新；已经被其他 PSD 共用的图片需要保持一致。共享 Sprite 的九宫边框也需要一致，避免 Unity Importer 设置互相覆盖。

将交付目录交给项目自己的 Unity 导入工具。本仓库不包含 Adapters，也不提供 Prefab 生成器；图集路由、Assets 路径、控件映射和业务逻辑由项目接入，见 [Unity 接入缺口](../../docs/UNITY-INTEGRATION.md)。

文字读取 Photoshop 的实际有效字号与点文本/段落类型。字体文件由项目的 fontKey 路由决定；PSD 缺失字体或项目映射不同仍会带来字形差异，需要核对预览。

本次迁移不包含私有项目验收样例，也未重新运行 Photoshop 或 Unity 验证。
