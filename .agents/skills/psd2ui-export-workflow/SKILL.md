# PSD 分析、配置与导出

使用已经安装的 PSD2UI Photoshop 插件处理真实 PSD。MCP 提供执行能力，本 Skill 规定处理流程；只有本文件或一张截图不能代替 Photoshop 连接。

## 先确定本轮范围

| 用户要求 | 本轮终点 |
| --- | --- |
| 看看这份 PSD、分析结构、给整理建议 | 完整分析与建议，不保存 PSD |
| 配好按钮、整理列表、调整状态/层级 | 确认的改动已保存到 PSD 与配置镜像 |
| 处理并导出、按已有配置导出 | 本次 JSON/PNG 导出结果 |
| 继续上次任务 | 沿用已确认方案，只完成剩余步骤 |

处理 PSD 时至少明确 PSD 绝对路径；配置时还需目标效果，导出时还需交付目录。未初始化 PSD 的界面模块名随配置方案确认。只分析时不要求提供模块或导出目录，更不要求 Unity 项目。仅检查连接时执行第 0 步后结束，不要求 PSD 路径。续做已有结果已达到本轮终点时，直接交付已知结果。

默认使用普通流程：修改后读回相关配置/结构一次。用户明确要求快速、不复测或只走流程时，使用快流程：以工具返回值继续，不追加读回、预检或生成后检查。两种流程都保留首次分析和必要确认。

本 Skill 目录及 references 可以整体移动。使用连接工具不依赖 Skill 的安装路径；终端调用需要另外定位工具根，见 [连接与调用](references/connection.md)。不要把复制 Skill 当成已经安装插件或 MCP。

## 0. 检查连接

优先使用客户端已经提供的 psd2ui_* MCP 工具。没有直接工具、但有终端能力和本地工具根时，使用连接参考中的 Portable 入口；两条路线择一复用。

开始任务和断连恢复时调用一次 `psd2ui_photoshop_status({"checkOnly":true})`。检查已安装的宿主与当前分支一致；CEP 和 UXP 的准备命令不能混用。检查无需已打开 PSD。

失败则报告原始原因和需要准备的具体项，不继续 PSD 操作。安装依赖、加载插件、Connect 属于独立准备步骤；用户已要求协助安装时按该范围处理，不把检查失败扩展成改插件源码。连接正常的同一执行段不反复检查。

## 1. 读取并形成方案

1. 用 `psd2ui_open_document` 打开/激活指定 PSD。
2. 用 `psd2ui_inspect_document` 读取完整已保存 Manifest、当前文档及导出目录；用 `psd2ui_snapshot` 读取 `rootLayerId:"document-root"` 的完整图层树。
3. 包含隐藏层、普通空组、已有组件和配置根以外的图层；区分“PSD 中存在”与“本次会导出”。没有 Manifest 或旧 JSON 也可以分析。旧 JSON 仅在需要比较时读取。
4. 输出当前层级与关键 ID、已有配置/差异、建议配置表（目标层、组件、角色、模板/预览/状态、改动理由）、需要用户决定的项。未确定用途的层保留，不为方便导出自动改名、忽略或删除。

只有分析任务到此结束。需要修改时，先确认方案；确认前不初始化、重组、保存、预检或导出。`preflight_export` 可能恢复状态预览，不能当作只读快照。

用户在本次会话已确认相同 PSD/方案时直接复用。用户明确指定的单项修改，若目标与参数可唯一确定且无需额外改动，读取核对后执行；明确要求“按现有配置原样导出”也不要再申请相同范围的授权。若发现必须增加改动、PSD 已变化或前置条件不成立，说明差异后再确定新方案。

## 2. 执行已确认的 PSD 处理

按需读取 [操作参考](references/operations.md)，使用当前工具声明和真实返回 ID。

- **未初始化**：需要保存配置时，调用 initialize_document，使用已确认的模块和 `document-root`。已有 Manifest 不重新初始化。
- **图片/文字类型及参数**：apply-node-preset 设置类型，update-node-parameters 修改既有参数。更换类型会套用预设，不能把它当作任意字段补丁。
- **层级与组件角色**：用 apply_confirmed_structure_plan；普通组、组件组合、改名、复制、角色等放在同一已确认计划中。CEP 额外的移动/解组/删除按参考中的条件使用；CCX 不支持这些扩展。
- **模板、预览、视口、视觉状态**：先完成组件内部的配置，再配置外层集合/状态。由刚创建组的返回值取得真实 ID；不能使用 @alias 作为后续 layerId，也不从同名层猜 ID。
- **已有文档修改模块**：当前日常 MCP 没有此入口，交由用户在面板保存模块；不要用重初始化或手写 sidecar 绕过。
- **引用和范围**：保持已确认的组件角色、模板、预览及资源身份。不要自动给所有组加前缀、把所有中文改英文，或将未确认的内容排除出导出。

普通流程在本阶段完成后 inspect 一次；涉及层级/模板/角色/状态时，snapshot 一次核对相关结果。快流程直接使用工具返回值。只要求配置时到保存结果结束。

## 3. 导出

确认所需配置已完成、当前 PSD 与交付目录正确后，调用 `psd2ui_export_bundle`，传精确的 `expectedDocumentPath` 与 `uiResPath`。它会保存配置和 PSD，并执行必要检查、输出 JSON/PNG。

直接复用工具的内部检查；用户要求单独诊断时才先调用 preflight_export。不要手工拼 Bundle、编辑 authoring 镜像或修改 Schema 来绕过导出问题。

报告本次工具实际返回的 `json`、`folder`、`sidecarPath` 和诊断；不要从历史目录猜成功，也不要把交付根当作 JSON 文件。按用户指定的终点交付，不自动扩展到 Unity、图集或业务代码。

## 失败与续做

- 普通工具失败：报告本次错误、失败步骤、已有产物和未完成项。不要为了清空诊断擅自扩大改动；是否修复按用户本轮授权范围决定，快流程不进入自动修复循环。
- UXP 写请求超时/断连：不代表取消。本分支没有 CEP 请求回执接口，不传 requestId/instanceId；先核对连接及当前 PSD 的实际状态，结果未确定时不自动重放。
- 续做记录：PSD/工具根/宿主/交付目录、用户已确认方案、完成步骤、返回的关键 ID 与路径、待确认请求。断连后先 Check，PSD 有实际变化时再刷新相关快照。
- 最终区分“仅分析”“配置已保存”“JSON/PNG 已导出”，注明普通读回或未复测及未解决问题。工具成功不等于视觉或运行交互验收。

Unity Adapter、字体/图集路由、Prefab 生成和业务接线由目标项目提供。用户需要它们时明确缺口，不能把 Photoshop 端导出报告成 Prefab 已完成。
